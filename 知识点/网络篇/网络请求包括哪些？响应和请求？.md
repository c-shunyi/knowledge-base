### 一、请求 (Request)

当你在浏览器中输入一个URL或点击一个按钮时，浏览器会构建一个请求报文并发送给服务器。这个请求报文包含以下几个关键部分：

#### 1. 请求行 (Request Line)

- **格式**：`方法 URL路径 协议版本`
    
- **示例**：`GET /api/users HTTP/1.1`
    
- **包含**：
    
    - **HTTP Method (请求方法)**：定义要对资源执行的操作。
        
        - `GET`：请求资源（获取数据）。
            
        - `POST`：提交数据（创建资源）。
            
        - `PUT`：更新完整资源。
            
        - `PATCH`：更新部分资源。
            
        - `DELETE`：删除资源。
            
        - `HEAD` / `OPTIONS`：用于获取头信息或检测服务器支持的方法。
            

#### 2. 请求头 (Request Headers)

- **作用**：向服务器传递关于此次请求的附加信息、客户端环境以及如何处理的指令。
    
- **常见请求头**：
    
    - `Host`：请求的目标域名和端口。
        
    - `User-Agent`：浏览器/客户端的身份标识字符串。
        
    - `Accept`：客户端能够处理的内容类型（如 `application/json, text/html`）。
        
    - `Content-Type`：**请求体**的编码类型（如 `application/json`, `application/x-www-form-urlencoded`）。
        
    - `Authorization`：携带身份验证凭证（如 `Bearer <token>`）。
        
    - `Cookie`：向服务器发送之前设置的Cookie数据。
        

#### 3. 请求体 (Request Body)

- **作用**：携带需要发送给服务器的数据。**并非所有请求都有请求体**（如 `GET`、`DELETE` 请求通常没有）。
    
- **常见格式**：
    
    - **JSON** (`application/json`)：现代API最常用的格式。
        
        json
        
        {"username": "john", "password": "123456"}
        
    - **表单数据** (`application/x-www-form-urlencoded`)：传统表单提交的格式。
        
        text
        
        username=john&password=123456
        
    - **表单数据与文件** (`multipart/form-data`)：用于上传文件。

### 二、响应 (Response)

服务器接收到请求后，进行处理，然后返回一个响应报文。

#### 1. 状态行 (Status Line)

- **格式**：`协议版本 状态码 状态消息`
    
- **示例**：`HTTP/1.1 200 OK`
    
- **包含**：
    
    - **HTTP Status Code (状态码)**：一个三位数代码，表示请求的结果。
        
        - `1xx`：信息性状态码（请求已接收，继续处理）。
            
        - `2xx`：**成功**（请求成功处理）。
            
            - `200 OK`：请求成功。
                
            - `201 Created`：资源创建成功。
                
        - `3xx`：重定向（需要进一步操作以完成请求）。
            
            - `301 Moved Permanently`：永久重定向。
                
            - `302 Found`：临时重定向。
                
        - `4xx`：**客户端错误**（请求包含错误或无法完成）。
            
            - `400 Bad Request`：请求语法错误。
                
            - `401 Unauthorized`：未授权/需要身份验证。
                
            - `403 Forbidden`：服务器理解请求但拒绝执行（无权限）。
                
            - `404 Not Found`：请求的资源不存在。
                
        - `5xx`：**服务器错误**（服务器处理请求时出错）。
            
            - `500 Internal Server Error`：服务器内部错误。
                
            - `502 Bad Gateway`：网关错误。
                
            - `504 Gateway Timeout`：网关超时。
                

#### 2. 响应头 (Response Headers)

- **作用**：服务器向客户端返回关于响应本身的元信息。
    
- **常见响应头**：
    
    - `Content-Type`：**响应体**的实际数据类型（如 `application/json; charset=utf-8`）。
        
    - `Content-Length`：响应体的长度（字节）。
        
    - `Set-Cookie`：服务器要求客户端设置Cookie。
        
    - `Cache-Control`：指示客户端如何缓存响应（如 `max-age=3600`）。
        
    - `Access-Control-Allow-Origin`：**CORS** 相关，指定哪些源可以访问资源（如 `*` 或 `https://example.com`）。
        

#### 3. 响应体 (Response Body)

- **作用**：服务器返回的实际数据内容，即前端代码需要解析和使用的内容。
    
- **常见格式**：
    
    - **JSON**：绝大多数API接口的返回格式。
        
        json
        
        {
          "status": "success",
          "data": {
            "id": 1,
            "name": "John Doe"
          }
        }
