| 特性       | `watch`                    | `watchEffect`      |
| -------- | -------------------------- | ------------------ |
| **依赖声明** | 需要手动指定                     | 自动收集依赖             |
| **执行时机** | 默认懒执行（可 `immediate: true`） | 默认立即执行一次           |
| **回调参数** | `(newVal, oldVal)`         | 没有参数               |
| **使用场景** | 精确监听某个数据的变化                | 自动响应依赖的副作用（更声明式）   |
| **典型应用** | 监听路由变化、数据变化后执行逻辑           | 日志、样式响应、调试、依赖较多的场景 |
## **1. `watch`**

### 特点

- **需要明确指定依赖源**（可以是 `ref`、`reactive` 属性、getter 函数）。
    
- 回调参数有 **新值** 和 **旧值**，可以方便地对比变化。
    
- 默认是 **懒执行**：只有依赖变化时才会触发。
    
- 更适合处理 **特定数据的变化副作用**。
    

### 例子

```js
import { ref, watch } from 'vue'  
const count = ref(0)  
watch(count, (newVal, oldVal) => {
   console.log('count 变化:', oldVal, '->', newVal) 
})`
```

👉 只有 `count` 变化时才会触发，能拿到 `newVal` 和 `oldVal`。

---

## **2. `watchEffect`**

### 特点

- **不需要指定依赖源**，内部会自动收集依赖（依赖追踪）。
    
- **立即执行一次**，然后依赖变化时再重新执行。
    
- 没有 `newVal` / `oldVal` 参数，只有副作用逻辑。
    
- 更适合处理 **自动收集依赖的副作用**，比如日志、样式、请求等。
    

### 例子

```js
import { ref, watchEffect } from 'vue'
const count = ref(0)  
watchEffect(() => {   
	console.log('count is:', count.value) 
})
```

👉 一开始就会执行一次，之后 `count` 改变也会执行。


## **4. 什么时候用哪个？**

- **用 `watch`**：
    
    - 需要知道新旧值差异。
        
    - 只关心某些特定数据的变化。
        
- **用 `watchEffect`**：
    
    - 想自动收集依赖，减少手写代码。
        
    - 做副作用处理（比如打印日志、响应样式）。
